## Project summary

`parse-efd-fiscal` is a Go CLI for Brazilian EFD/SPED fiscal auditing. It imports SPED and XML fiscal files, persists records in MySQL through GORM v1, processes inventory movements, and generates Excel reports.

Evidence: `README.md`, `go.mod`, `main.go`, `Models/`, `read/`, `exec/`, `SpedDB/`, `Controllers/`, `tools/SpedConvert.go`.

## Architecture map

- CLI orchestration: `main.go` defines flags including `-schema`, `-importar-sped`, `-importar-xml`, `-inventario`, `-anoInicial`, `-anoFinal`, `-excel`, and `-h010`.
- Configuration: `config/config.go` loads database, worker, digit-code, and SPED path settings from `.env` via `pkg/env/env.go`.
- Persistence: MySQL via `github.com/jinzhu/gorm` and `github.com/go-sql-driver/mysql`; schema lifecycle is in `SpedDB/`.
- File ingestion: `read/sped.go`, `read/xml.go`, and `read/control.go` traverse source files and route processing.
- Parser/insert dispatch: `exec/` contains SPED, NFe XML, and CFe XML routines.
- Domain models: `Models/Bloco0`, `Models/BlocoC`, `Models/BlocoH`, `Models/NotaFiscal`, `Models/CupomFiscal`, and `Models/Inventario.go`.
- Inventory/reporting workflows: `Controllers/InventarioController.go`, plus emerging `Controllers/service` and `Controllers/repository` layers.
- Utilities: `tools/` has conversion helpers and constants; `pkg/worker` contains a worker pool used by inventory processing.
